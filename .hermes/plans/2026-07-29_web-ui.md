# TreeBot Web UI Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** A mobile-friendly, button-driven web interface for TreeBot so crews can do everything without typing WhatsApp commands.

**Architecture:** Keep the existing Express server and SQLite DB as the single source of truth. Add a JSON REST API (`/api/*`) that reuses the existing command handlers and db helpers directly (no duplicated business logic). Serve a zero-build, single-page vanilla JS frontend from `public/` — no React/build step, deployable on Railway as-is. WhatsApp webhook remains fully functional in parallel.

**Tech Stack:** Node.js, Express (existing), better-sqlite3 (existing), vanilla HTML/CSS/JS (no new runtime deps).

---

## Design Decisions (locked)

- **No command input in the UI.** Every action is a form/button/dropdown. Data comes from API endpoints, actions go through API endpoints.
- **Reuse command handlers where they mutate state** (`drop`, `addstock`, `setalloc`, `addkey`, section management, undo, sync, import) so action history, activity logs, undo, and Sheets auto-sync all behave identically to WhatsApp.
- **Use db helpers directly for read-only dashboard data** (structured JSON), since handlers return WhatsApp-formatted markdown strings.
- **Web actions are attributed** to a single web user identity: `from = 'web'`, `contactName = 'Web UI'`. Undo on web undoes the last web action. (Multi-user auth is out of scope — see Risks.)
- **No new npm dependencies** except none at all: frontend is static files, API is plain Express with the existing `express.json()`.

## UI Screens (single page, tab navigation)

1. **Dashboard** — inventory totals, allocation progress bars per section, remaining counts.
2. **Drop** (most-used, big touch targets) — pick section → pick request key → quantity stepper → "Log Drop". Shows remaining allocation live.
3. **Stock** — inventory table + "Add Stock" form (key dropdown + quantity).
4. **Allocations** — table per section + "Set Allocation" form.
5. **Keys** — request key list + "Add Key" form.
6. **Sections** — list + add/edit/delete (delete has a confirm dialog, mirroring `/removesection confirm`).
7. **Activity** — recent activity log + "Undo last action" button.
8. **Sheets** — connection status, sync-now buttons, import preview/confirm flow.

All forms validate client-side AND reuse server-side validation from handlers. Errors from handlers are shown in a toast/banner.

```js
const express = require('express');
const db = require('./database');
const sheets = require('./sheets');
const sync = require('./sync');

const router = express.Router();

router.get('/inventory', (req, res) => res.json(db.getAllInventory()));
router.get('/sections', (req, res) => {
  const sections = db.getAllSections();
  res.json(sections.map(s => ({ ...s, stats: db.getSectionStats(s.id) })));
});
router.get('/keys', (req, res) => res.json(db.getAllRequestKeys()));
router.get('/species', (req, res) => res.json(db.getAllSpecies()));
router.get('/allocations', (req, res) => res.json(db.getAllAllocations()));
router.get('/allocations/:section', (req, res) => {
  const allocs = db.getSectionAllocations(req.params.section);
  res.json(allocs.map(a => ({
    ...a,
    dropped: db.getDropsBySectionAndKey(a.section, a.request_key_id)?.total_dropped || 0
  })));
});
router.get('/logs', (req, res) => res.json(db.getRecentLogs(50)));
router.get('/sheets/status', (req, res) => res.json({
  connection: sheets.getConnectionStatus(),
  sync: sync.getSyncStatus()
}));

module.exports = router;
```

### Task 3: Mutation API endpoints (reuse command handlers)

**Objective:** Web actions go through the same handlers as WhatsApp, preserving undo/logging/sync.

**Files:**
- Modify: `src/api.js`

**Step 1: Failing test** — POST `/api/drops` with `{quantity, requestKey, section}` then check inventory decreased and `db.getLastUserActions('web')` has the action.

**Step 2: Implement** — add to `src/api.js`:

```js
const commands = require('./commands');
const WEB_USER = { from: 'web', name: 'Web UI' };

function handle(handler) {
  return async (req, res) => {
    try {
      const text = await handler(req.body, WEB_USER.from, WEB_USER.name);
      const ok = typeof text === 'string' && !text.startsWith('❌');
      res.status(ok ? 200 : 400).json({ ok, message: text });
    } catch (e) {
      res.status(500).json({ ok: false, message: e.message });
    }
  };
}

router.post('/drops', handle(commands.drop));
router.post('/stock', handle(commands.addstock));
router.post('/allocations', handle(commands.setalloc));
router.post('/keys', handle(commands.addkey));
router.post('/sections', handle(commands.addsection));
router.put('/sections/:id', (req, res, next) => {
  req.body = { section: req.params.id, description: req.body.description };
  handle(commands.editsection)(req, res, next);
});
router.delete('/sections/:id', (req, res, next) => {
  req.body = { section: req.params.id, confirmed: req.query.confirmed === 'true' };
  handle(commands.removesection)(req, res, next);
});
router.post('/undo', handle(commands.undo));
router.post('/sync', (req, res, next) => {
  req.body = { target: req.body.target || null };
  handle(commands.sync)(req, res, next);
});
```

**Step 3:** Tests pass + manual: `curl -X POST localhost:3000/api/drops -H 'content-type: application/json' -d '{"quantity":1,"requestKey":"068","section":"6"}'` then `POST /api/undo`.

**Step 4: Commit** — `"feat: mutation API endpoints reusing command handlers"`

## Risks, Tradeoffs, Open Questions

- **No authentication by default** — anyone with the Railway URL can mutate inventory. Mitigated by optional `WEB_UI_TOKEN` (Task 8). A full multi-user login is out of scope; if crews need per-user attribution later, add a name picker stored in localStorage and pass it as `from`/`contactName`.
- **Handlers return WhatsApp markdown strings** — the API returns them as `message`; UI shows them as plain text in toasts (acceptable), and uses structured endpoints for rendering (preferred). No refactor of handlers into structured returns — avoids touching battle-tested logic.
- **Undo is global per identity** — web UI shares one `web` identity, so any crew member can undo the last web action. Documented behavior.
- **Railway ephemeral SQLite** — unchanged; Sheets remains the durable mirror. Web UI doesn't worsen this, but consider a follow-up: nightly backup endpoint or Railway volume.
- **Open question:** Do you want the WhatsApp bot to eventually *link* to the web UI (e.g. reply with the Railway URL on `/help`)? One-line change once deployed.
